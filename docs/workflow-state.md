# Workflow state and checkpoints

M2 introduces persistent, agent-neutral workflow state.

## Start a workflow

    llmatic workflow start --task KT-100

The runtime creates a UUID-backed workflow run under the configured state directory and stores a current snapshot.

## Inspect state

    llmatic status

or:

    llmatic workflow status --json

## Transition state

    llmatic workflow transition task-validated
    llmatic workflow transition repo-analyzed
    llmatic workflow transition branch-created

Transitions are validated by the runtime. An agent cannot jump directly from TASK_SELECTED to READY_TO_MERGE.

## Capability execution

Detected repository capabilities can be executed through:

    llmatic run typecheck
    llmatic run test
    llmatic run build

The executor uses structured executable arguments generated by repository detection. It does not execute the human-readable command string.

Every capability execution is appended to the active workflow as a checkpoint.

## Permission enforcement

Quality gates use the runQualityGates permission.

Tests use the more specific runTests permission.

Permission values:

- auto: execute immediately
- ask: require --approve
- deny: reject execution

Example:

    llmatic run test --approve

## Persistence model

The runtime stores:

    .llmatic/state/current.json
    .llmatic/state/runs/<run-id>.json

Writes use a temporary file and rename strategy. The run history and current snapshot are updated together by the state-store API.

## Current state machine

    TASK_SELECTED
      -> TASK_VALIDATED
      -> REPO_ANALYZED
      -> BRANCH_CREATED
      -> IMPLEMENTING
      -> LOCAL_VALIDATION
      -> CODE_REVIEW
      -> READY_TO_PUSH
      -> PUSHED
      -> PR_OPEN
      -> REMOTE_CI
      -> FINAL_REVIEW
      -> READY_TO_MERGE
      -> COMPLETED

FIXING loops are allowed from implementation/validation/review/remote-CI states. Any active state can move to FAILED where explicitly defined by the transition map.

The next milestone will add orchestration commands that advance these states automatically from gate results rather than requiring manual transitions.
